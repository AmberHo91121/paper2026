# 步驟 5　洞見萃取（Insight Extractor）SPEC

> 共通原則見 [AI_agent化工作流程草案.md](AI_agent化工作流程草案.md)。這是整條流程的最後一站。

## 目的

現有 `insight` skill 只做到 Quote＋情境＋Code；這一步補上 Theme 到 Implication，並把「證據層」和「詮釋層」切開，避免 agent 捏造因果。

## 九層框架

| 層級 | 問題 | 性質 |
|---|---|---|
| ① Raw Data | 使用者說了什麼？ | 證據層 |
| ② Context | 什麼情況下說？ | 證據層 |
| ③ Behavior | 使用者做了什麼？ | 證據層 |
| ④ Code | 這段資料代表什麼？ | 證據層 |
| ⑤ Theme | 哪些 Code 是同一類？ | 聚類，可回溯 |
| ⑥ Pattern | 多人／多情境出現什麼規律？ | 聚類，可回溯 |
| ⑦ Why | 為什麼有這個規律？ | 詮釋層（推論） |
| ⑧ Insight | 這告訴我們什麼？ | 詮釋層（推論） |
| ⑨ Implication | 設計應如何回應？ | 詮釋層（推論） |

## 階段

| 階段 | 觸發 | 輸出（`06_結果/`） |
|---|---|---|
| 逐句編碼 | 單份逐字稿到位即可，逐份跑 | `01_編碼總表.md` |
| 聚合（跨受訪者） | 使用者口頭宣告「全部受訪者到齊」 | `02_Theme彙整.md` |
| 詮釋 | 接在聚合之後 | `03_Pattern卡片.md`、`04_對應研究框架.md` |

### 逐句編碼階段

- 以「有資訊量的段落」為單位，填 Raw Data（`[時間戳] 語者：「原文」`，不可編造）、Context、Behavior（實際操作，不只語言）、Code
- **確認點**：Code 貼著資料，還不出現「為什麼」
- 發現訪談題目問不出資料時，可直接叫出步驟 3 的框架修正階段，不必編完才反映

### 聚合階段：Theme 與 Pattern

- Theme：語意相近的 Code 收斂成類別
- Pattern：**≥ 2 位受訪者且 ≥ 2 個情境**出現同類 Code；未達門檻者記為「個案觀察」。樣本 < 8 人時加註涵蓋比例
- **確認點**：Theme 有無硬湊；Pattern 是否具代表性

### 詮釋階段（全部推論，須使用者確認）

每個 Pattern 提出 Why（最多 2 個候選並排序）、Insight（標明由哪個 Why 推導）、Implication（具體可執行，不空泛）。另將 Pattern 依 `03_研究架構` 的構念／Objectives 分類，寫成 `04_對應研究框架.md`（資料蒐集**後**「Pattern ↔ 框架」）。

Pattern 卡片格式：

```markdown
### Pattern：<名稱>

**涉及**：<受訪者（情境／功能）>
**支撐 Theme**：…
**支撐 Code**：…

**Why（推論）**：候選 1 … ／ 候選 2 …（排序與理由）
**Insight**：…
**Implication（設計機會）**：…
```
