## 1. 為什麼要這樣設計

你的研究背景是設計/HCI，但問題本質常常牽連心理學、認知科學、資訊科學。單純用 HCI 關鍵字查文獻容易漏掉其他領域已經解決過、或用不同詞彙描述同一個現象的研究。這個 agent 的目的不是「幫你查資料」而已，而是**幫你在開始深讀前，先看清楚這個題目的知識地圖長什麼樣**：哪些是地基（背景知識）、現在戰場在哪（近三年研究）、還有哪裡沒人打過（研究缺口）。

三段對應到三種不同的認知任務，性質不同，所以跟洞見萃取 Agent 一樣採 **Stage A/B/C 分階段**，而不是一次生成整包丟給你——這是你這次明確要求的：**每一步你確認沒問題才進行下一步，避免不必要的浪費**（尤其 Stage B 如果查詢方向錯了，Stage C 的缺口分析會整個建立在錯誤基礎上）。

## 2. 三階段總覽

| Stage | 對應你的分類 | 問題 | 產出 |
|---|---|---|---|
| A | 領域背景知識 | 這個議題的地基是什麼？ | 奠基/經典文獻清單 |
| B | 近三年相關研究 | 現在戰場在哪？ | 近三年高影響力研究清單 |
| C | 研究缺口 | 哪裡還沒人做，值得做？ | 缺口草案（待你確認） |

**關鍵性質**：A、B 是「檢索＋分級」，靠得住的判準（引用數、來源等級），machine 可以做到八九分；C 是「歸納＋判斷」，本質上是推論，agent 只能**先草擬**，不能替你下定論——這點延續你在洞見萃取 spec 裡定下的規則（詮釋層必須標「推論」、人工覆核才能定稿）。

## 3. 觸發機制

- Stage A 完成 → 停下來等你看過清單，確認「這個議題的背景知識地圖對不對、有沒有遺漏的重要脈絡」→ 你說可以，才進 Stage B
- Stage B 完成 → 停下來等你看過近三年清單，確認「檢索方向/關鍵字有沒有偏掉」→ 你說可以，才進 Stage C
- Stage C 完成 → 產出缺口草案，**必須停在這裡等你判斷**，不會自動接到 Agent 2（精讀陪讀）或其他下游 agent

跟洞見萃取一樣：整條線目前是**手動觸發**，不接檔案監看或自動化機制，每個 stage 之間的「可以繼續」由你明確講出來。

## 4. 資料來源與優先序

依你的指定：

1. **ACM Digital Library**（優先）
2. **Google Scholar**
3. **Web of Science**
4. 其他（視主題延伸，例如 PsycINFO/APA PsycNet、Semantic Scholar 補查引用數）

**大型研討會清單**（Stage B 判斷「大conference」用）：CHI、CSCW、UIST、DIS、HCII、TEI（你指定，之後可再補）

**已定案**：以 HCI/設計為主軸，上述「大conference」清單只套用在這個主軸上。心理學、資訊科學等其他領域的文獻視為**輔助補充**，不強制套用同一套場刊門檻——只要是該領域公認的高信度來源（同儕審查期刊/會議）即可納入，不需要另建一份跟 HCI 同等嚴格的清單。

## 5. Stage 詳細規格

### Stage A — 領域背景知識

- **輸入**：研究問題/主題關鍵字
- **判準**：**不設年份下限**，只看是否為常被後續文獻引用、或被教科書/綜述引用的經典（你的原話）
- **處理**：agent 需要能分辨「這篇常被引用」跟「這篇只是剛好引用數高但其實是綜述裡順帶提到」的差別——初步做法是看該篇是否**在多篇不同的近期論文的 Related Work / Background 段落中被引用**，而不是只看引用數字
- **輸出**：清單，每筆包含：
  - 標題、作者、年份、來源
  - 一句話說明「這篇奠基了什麼」（例如：提出了 XX 理論框架 / 定義了 XX 現象的分類）
  - 為什麼判定為經典（哪些後續文獻引用它作為基礎）
- **人工 review 點**：你熟悉的地基文獻 agent 有沒有漏掉；agent 判斷「經典」的理由是否站得住腳

### Stage B — 近三年相關研究

- **輸入**：Stage A 確認後的研究方向（可能因為 A 的結果而微調關鍵字）
- **判準**：
  - 發表於前述大型研討會（CHI/CSCW/UIST/DIS/HCII/TEI 等）
  - 引用數 10+（你的原話：「cite over 10+」）
- **處理**：**已定案**——引用數 < 10 但發表 < 1 年的論文，不直接排除，改標註「🌱新興/尚未累積引用」附加列在清單中，由你自己判斷要不要納入細讀範圍
- **輸出**：清單，每筆包含：
  - 標題、作者、年份、發表場刊
  - 引用數
  - 一句話關聯性說明（這篇在做什麼、跟你的題目哪裡有關）
- **人工 review 點**：檢索關鍵字/方向對不對，避免 Stage C 建立在偏掉的基礎上

### Stage C — 研究缺口分析

- **輸入**：Stage A + Stage B 確認後的清單
- **agent 先初步草擬**，依你指定的三個問題分析每個候選缺口：
  1. **這個缺口為什麼沒有人做？**（方法限制？資料難取得？領域间沒人跨接？還是其實有人做但用不同詞彙、沒被搜到？）
  2. **這個缺口有價值嗎？**（對理論有貢獻，還是只是填補瑣碎的組合）
  3. **補上這個缺口可以產生什麼貢獻？**（理論貢獻／方法貢獻／應用貢獻，具體講清楚，不要空泛）
- **輸出**：缺口卡片，每張缺口包含上述三個問題的草擬回答，**明確標註「推論/草案，待確認」**
- **人工 review 點**：**這是全流程唯一規定要你覆核才能定稿的節點**——agent 提案，你判斷這個缺口是不是真的成立、值不值得做

## 6. 輸出文件結構（提案）

**已定案**：所有階段輸出一律為純 Markdown 檔案，不生成 HTML 或其他格式。這個 agent 只負責產出文獻地圖，不處理簡報/報告轉譯（原本規劃的簡報生成 agent 已確認不需要，這件事如果要做，由你自己視需要手動處理）。

```
文獻檢索_<議題名稱>/
  01_背景知識.md      — Stage A 產出
  02_近三年研究.md     — Stage B 產出
  03_研究缺口.md       — Stage C 產出，缺口卡片格式：

  ### 缺口：<一句話描述>

  **相關背景文獻**：（連到 01 的條目）
  **相關近期研究**：（連到 02 的條目，哪些論文做了相近但不完全的東西）

  **為什麼沒人做（推論，待確認）**：
  ...

  **有沒有價值（推論，待確認）**：
  ...

  **補上能產生什麼貢獻（推論，待確認）**：
  ...
```

**先採用卡片格式**（如上），跟洞見萃取的 Pattern 卡片邏輯一致，方便回溯到背景/近期文獻。如果之後缺口數量一多、你覺得卡片不好橫向比較，隨時可以再改成表格。
