# 研究主題 Repo 資訊架構草案

> 你把先前「每個研究主題各自開一個 repo」的決定改成「一個大 repo，裡面容納多個研究主題」。這份文件草擬這個大 repo 的資訊架構，也是[洞見萃取Agent_SPEC.md](洞見萃取Agent_SPEC.md)等文件裡「D. 版本控制邏輯不一致」缺口的正式解法——所有 agent 的產出現在都收斂進同一個 git 版本控制的結構裡，不再各自為政。
> 帶 ❓ 待確認欄位供你人工 review。

## 1. 為什麼這樣分資料夾

你列的七個分類（編輯歷程、文獻探討、研究問題、研究架構、研究方法、結果、討論）剛好對應到一篇論文的標準章節順序，也剛好對應到 Agent 1-5 的產出順序（其中「討論」這格已無對應 agent，見第 2 節）。用同一套邏輯分資料夾，你之後不管是要「查這個主題目前進度到哪」還是「回頭看某一版研究問題長怎樣」，都能直接照論文章節的直覺去找，不用另外記一套 agent 編號對應表。

## 3. 「編輯歷程」跟 git commit history 的分工

Git 本身就有完整的版本紀錄，但 `git log` 對人不太友善（要找某次改動要慢慢翻）。所以每個主題資料夾內建一個 `00_編輯歷程.md`，只記**你會想回頭看的里程碑**（例如「Stage B 確認 Problem/Aim/Objectives」「補了酷兒女性這條研究問題」），細節層級的每次小修改就交給 git commit history，不用兩邊都鉅細靡遺地記。

## 4. 這如何解決「A／C／D」三個缺口

- **A1（Agent 4 輸入斷點）**：已直接修正 [AI_agent化工作流程草案.md](AI_agent化工作流程草案.md) 裡 Agent 4 的輸入欄位，改成讀 `03_研究架構/研究架構.html`
- **A2（Agent 2→3 缺彙整步驟）**：已修正 [研究架構Agent_SPEC.md](研究架構Agent_SPEC.md)，Stage A 現在明確讀整個 `01_文獻探討/` 資料夾（不只一篇論文），論文一多的時候先做簡短彙整再評判
- **C（缺轉錄步驟）**：`05_原始資料/` 給逐字稿一個明確的家，但**轉錄本身還是沒有 agent 覆蓋**——這仍然是一個待補的缺口，不是這次資料夾重整就能解決的，見第 6 節
- **D（版本控制不一致）**：現在 Agent 1、2、3 的產出全部收斂進同一個 git repo，不再是「只有 Agent 3 有版本控制」的不一致狀態——`git log` 對整個主題資料夾一體適用

## 5. Public/Private：已定案為 Private

改成一個大 repo 裝所有主題後，重新確認過的結果：**Private**。網頁不透過 GitHub Pages 發佈，你自己手動在本機打開 html 檔案看，跟現在這幾份 demo 檔案的看法一樣。這樣不用考慮 GitHub Pro 付費方案，git 純粹拿來做版本控制。

## 6. 缺口進度更新

- **轉錄步驟：已解決，不需要新 agent**——你既有的 Notion 工具已經覆蓋訪談錄音轉逐字稿這段，`05_原始資料/` 就放 Notion 匯出/整理後的逐字稿即可
- **框架站不住腳的迴圈：已設計**——見 [研究架構Agent_SPEC.md](研究架構Agent_SPEC.md) 新增的 **Stage D（框架修正協作）**。不是自動觸發的迴圈機制，是你發現落差時主動找我討論：先定位問題屬於哪一種偏誤類型（構念定義誤判／方法產出資料類型不對／樣本邊界條件不符／構念間關係假設錯了／範圍設定過大過小），再給 2-3 個有憑有據的修正方向讓你選，確定後更新 `02_研究問題/`、`03_研究架構/`，並在 `00_編輯歷程.md` 記一筆
- **知識庫策展、排程協調、簡報/報告生成：確認都不需要**——原本設想的跨主題回饋、行事曆協調、簡報生成三個 agent 全部拿掉，`_cross-topic-index.md` 這個佔位檔案也拿掉，整條 agent 鏈到 Agent 5（洞見萃取）為止，`07_討論/` 資料夾保留但改為你自己手動寫

## 7. 這輪新修的漏洞

- **Stage D 補上第 6 種偏誤類型「文獻支撐不足」**：發現框架構念/方法在既有文獻裡找不到支撐時，先退回 Agent 1/2 補查文獻，而不是直接改框架——見 [研究架構Agent_SPEC.md](研究架構Agent_SPEC.md)
- **Stage D 修正後新增下游影響檢查**：框架修正後，已完成的 `04_研究方法/`、已蒐集的 `05_原始資料/` 要明確標註是否受影響、要不要標記「基於修正前版本」
- **[洞見萃取Agent_SPEC.md](洞見萃取Agent_SPEC.md) 補上反向迴圈連結**：Stage A 編碼時發現訪談大綱有問題，可以主動觸發 Agent 3 的 Stage D，不用忍到編碼完
- **[研究設計Agent_SPEC.md](研究設計Agent_SPEC.md) 新增研究倫理與同意書**：強制產出，涵蓋 IRB 評估、知情同意重點、敏感資訊處理、招募文宣用語考量
- **Agent 4 技法選擇的「原因」新增文獻佐證要求**：優先引用 `01_文獻探討/` 既有文獻的方法論慣例，不能只憑經驗感覺
- **Code 詞彙表**：不用 Agent 8，改用 repo 根目錄一份輕量的 `_code-vocabulary.md`，Agent 5 發現語意相近的新 Code 時提醒你，你決定要不要統一
- **Pattern 判定門檻／Why 候選數**：定案為「2 位受訪者＋2 個情境，小樣本額外標涵蓋比例」「Why 最多 2 個候選排序」，見 [洞見萃取Agent_SPEC.md](洞見萃取Agent_SPEC.md)
