## 共通原則（各 SPEC 不再重述）

1. **手動觸發、逐 Stage 停下**：每個 Stage 結束都等使用者明確說「可以繼續」，不做檔案監看或自動串接。
2. **推論要標記**：詮釋性內容（缺口判斷、邏輯評判、Why／Insight、Significance 等）一律標「推論」，agent 只提案，由使用者定稿。
3. **決策附原因／限制／影響**：不只寫「選了什麼」。
4. **可回溯**：引用不可編造；結果能回溯到原文，設計能回溯到框架。
5. **批次先確認**：處理多篇論文或多份資料前，先列候選與優先序，確認後依序做、每批回報。
6. **版本靠 git**：檔案永遠放最新版，舊版查 git log；里程碑記在主題的 `00_編輯歷程.md`。push 前先問。
7. **主題資料夾由使用者指定**：子路徑依資料夾慣例，不用每次決定。

## 不做的事

排程協調、簡報／報告生成、知識庫策展三個 agent 已確認不需要；`07_討論/` 由使用者手動撰寫。
