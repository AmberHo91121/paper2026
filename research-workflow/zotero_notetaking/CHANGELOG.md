# 考考男 — 變更紀錄

## 一、設計階段（SPEC.md 定案過程）

| # | 內容 | 原因 |
|---|---|---|
| 1 | 觸發機制定為「捲到內文最後一頁」+「累積閱讀時長 ≥ 門檻（淺讀 20 分鐘／精讀 60 分鐘）」兩個條件同時成立 | 原始構想是純計時，但單靠計時容易誤觸發（例如中途離開）；改成「時長下限 + 到達最後一頁」的組合，比較貼近「真的讀完」 |
| 2 | 淺讀跳過機制：只跳過淺讀題組本身，不影響整體測驗流程 | 確認「跳過」的語意，避免跳過變成整個測驗都不考 |
| 3 | 出題資料來源定為「LLM 讀全文 + 使用者的 Zotero 劃線/annotation」混合 | 純讀全文出題無法反映使用者實際關注的重點 |
| 4 | 開放式問題（值不值得讀 / 可以參考什麼）不需要評分或對照正解 | 這兩題的目的是讓使用者當下記錄自己的想法，寫下來本身就是目的，不是給系統評估用的 |
| 5 | 靜音機制：連續 3 次 dismiss → 全域靜音 3 小時（所有論文都適用，不分篇） | 避免頻繁跳出提問造成干擾疲勞 |
| 6 | 筆記紀錄方式定為獨立本地 `notes/` 資料夾（`_總紀錄.md` + 每篇論文一個 md），不寫回 Zotero 內部筆記系統 | 使用者明確選擇要跟 Zotero 筆記系統脫鉤、方便被其他工具讀取 |
| 7 | 移除語音輸入功能 | 使用者確認不需要，且 Zotero 閱讀器底層是 Firefox 系架構，瀏覽器原生語音辨識支援度低，移除可以簡化技術風險 |
| 8 | 修正 spec 文字「淺讀 7 小題」→「淺讀 5 小題」 | 使用者已把淺讀題目改成類型/脈絡/前提/貢獻+值得讀共 5 題，但標題文字沒同步更新，屬於單純的文字修正 |

## 二、外掛開發階段（`plugin/` 程式碼迭代紀錄）

| # | 內容 | 原因 |
|---|---|---|
| 1 | 技術可行性調查：確認 `Zotero.Reader.getByTabID(tabID).state.pageIndex`（頁碼）、閱讀時長追蹤、`registerEventListener('renderToolbar', ...)`（UI 注入點）等 API 在社群外掛中已被驗證可用 | 動手寫程式前先確認地基站不站得住腳，降低後續推翻重來的風險 |
| 2 | 建立 MVP 骨架：`manifest.json` / `bootstrap.js` / `src/kaokaonan.js` / `src/avatar.svg` / `README.md`，先做「偵測到最後一頁+時長門檻→跳出提示」+ 工具列按鈕 | 先驗證觸發邏輯這條技術地基，不一次做完整功能 |
| 3 | 打包指令從 `Compress-Archive -DestinationPath xxx.xpi` 改成先壓 `.zip` 再改副檔名 | PowerShell 的 `Compress-Archive` 只接受 `.zip` 副檔名，直接指定 `.xpi` 會報錯 |
| 4 | `manifest.json` 的 `strict_max_version` 從 `7.*` 改成 `10.*` → 之後又補上 `10.0.*` 精確格式 | 使用者實際 Zotero 版本是 10.0.1，遠超過原本設定的相容上限 7.x |
| 5 | 一度加上 `"type": "bootstrap"` 和 `gecko` 相容區塊 | 參考另一個已驗證可在 Zotero 10 運作的外掛（zotero-reading-tracker）manifest 結構，嘗試對齊格式 |
| 6 | 移除空字串的 `update_url`，改成必填的佔位網址 | 從 Browser Console 的詳細錯誤（`applications.zotero.update_url not provided`）確認這才是真正導致安裝失敗的原因，之前的版本猜測都不是根因 |
| 7 | 打包方式從 `Compress-Archive` 改成自訂 `build.ps1`（用 .NET `ZipArchive` 手動控制路徑分隔符號） | Windows 版 `Compress-Archive` 產生的 zip 內部路徑用反斜線，不符合 zip 規格的正斜線，Firefox/Zotero 的 zip 解析器可能因此拒裝 |
| 8 | 工具列按鈕元素從 XUL 的 `toolbarbutton`/`command` 事件改成標準 HTML `button`/`click` 事件 | reader 工具列是 React/HTML 渲染的介面，不是 XUL，用 XUL 元素會建立成沒有作用的空元素 |
| 9 | log 機制加上 `Services.console.logStringMessage()`，跟 `Zotero.debug()` 並行輸出 | `Zotero.debug()` 預設不會顯示在 Browser Console (`Ctrl+Shift+J`)，導致原本判斷不出外掛到底有沒有執行 |
| 10 | 新增浮動陪伴頭像，一開始掛在 Zotero 主視窗、加上重試機制（`Zotero.getMainWindow()` 在 `init()` 當下可能還拿不到主視窗） | 使用者希望有常駐陪伴的視覺角色，不只是工具列上的小按鈕 |
| 11 | 浮動頭像改成掛在該篇論文 reader 自己的 iframe 裡，不再掛主視窗常駐 | 使用者要求頭像只在開著論文時才該出現，論文沒開就不該有東西 |
| 12 | 頭像圖片從 `<img src="...外掛檔案路徑...">` 改成直接內嵌 SVG 字串 | reader 頁面的內容安全性限制擋掉了跨來源載入外掛檔案的請求（`jar:file:...xpi!/...` 被拒絕），內嵌字串完全不需要額外載入資源，直接繞過限制 |
| 13 | 「目前在讀哪一篇」的判斷邏輯從查 `Zotero_Tabs.selectedID` 改成追蹤已知 reader 清單、用 iframe focus 狀態判斷；sessions 改成用 itemID 而不是 tabID 當 key | 原本的作法假設 PDF 一定是開在主視窗的分頁裡，但使用者的 Zotero 可能把 PDF 開在獨立視窗，導致完全查不到對應的 reader |
| 14 | 決定先用固定題目（SPEC.md 4.1/4.2 定義的題組）做完整問答流程，暫不接 Claude API | 接 LLM 出題需要額外設定 API key、有呼叫成本，使用者選擇先驗證整個互動流程本身，出題品質留到之後再處理 |
| 15 | 模式選擇從原生 `confirm()`（開始淺讀還是精讀，只能兩個按鈕）改成自訂三按鈕彈窗（開始淺讀／跳過直接精讀／取消） | 原生對話框做不出三個選項，使用者明確要求要有三顆按鈕的介面 |
| 16 | 新增「作答回顧清單」面板，列出所有題目與已作答內容 | 使用者希望已經作答過的論文再點頭像時，能看到過去填寫的內容，而不是只顯示「已完成」 |
| 17 | 接上檔案持久化：每次作答（不管全部答完或只答幾題）都寫進 `notes/<論文標題>.md`，並更新 `notes/_總紀錄.md` 彙總索引 | 原本所有作答只存在記憶體裡，重啟 Zotero 就會消失；這一步照 SPEC.md 第 6 節的設計把資料真正落地 |
| 18 | 大改版整體互動流程：① 第一次點擊直接進淺讀（拿掉模式選擇彈窗）② 淺讀題目卡片上加「跳過剩餘淺讀，直接精讀」按鈕 ③ 淺讀整組答完後才另外問要不要繼續精讀。原本用 `win.prompt()` 依序跳提示框的作法，改成單一持續存在的題目卡片（`showQuestionCard`），一次一題、可前進、可跳題 | 使用者要求的介面流程改動，讓「淺讀優先、精讀是進階選項」這個設計意圖更直接地反映在互動上 |
| 19 | 修正「切換到精讀模式後，回顧清單跟 md 筆記檔案都只顯示/寫入目前模式的題目」的 bug，改成不管目前在哪個模式，都同時列出/寫入淺讀+精讀兩組內容 | 使用者回報「檢視作答紀錄無法看到全部的回覆」，追出原因是 `showAnswerReview` 和 `writePaperNote` 都只用 `QUESTION_SETS[session.mode]`（目前模式）取資料，導致切到精讀後，淺讀的紀錄在畫面上「消失」、在檔案裡被覆蓋掉 |
| 20 | 新增「編輯」功能：回顧清單裡已回答的題目旁邊加編輯按鈕，題目卡片上加「查看/編輯已作答」入口，改完會同步寫回 md 檔案 | 使用者希望能回頭修改先前的作答內容，而不是只能看不能改 |
| 21 | 回顧清單裡的編輯按鈕從「只有已回答的題目才有」改成「不管有沒有回答過都有」（未回答顯示「填寫」、已回答顯示「編輯」） | 使用者要求所有題目在回答總覽裡都應該可以編輯，不限於已作答過的 |

## 三、目前狀態（截至這份紀錄）

- 核心技術地基（頁碼偵測、閱讀時長追蹤、UI 注入）已驗證在 Zotero 10.0.1 上可運作
- 完整問答互動流程（淺讀優先、可跳精讀、可回顧編輯）已可用，但**題目仍是寫死的固定內容，尚未接 LLM 動態出題**
- 作答紀錄會即時寫入 `notes/` 資料夾，路徑目前寫死在程式碼裡（`kaokaonan.js` 的 `NOTES_DIR`），不是可攜式設定
- 尚未實作：LLM 動態出題、節流/靜音機制（連續 dismiss 3 次自動靜音 3 小時）、`notes/` 路徑改成可設定
