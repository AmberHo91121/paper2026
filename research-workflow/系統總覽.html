五個步驟

1

文獻蒐集

SPEC

Stage A 背景知識 → Stage B 近三年研究 → Stage C 研究缺口。ACM＞Google Scholar＞WoS，以 HCI 大會為主軸，心理學/資訊科學輔助。輸出純 Markdown，不生成 HTML。

2

精讀陪讀

SPEC

依 Critical Form 13 欄位整理單篇論文，Stage 0 確認收錄與優先序 → Stage A 逐段導讀＋Critical Form 草稿 → Stage B 你確認 → Stage C 上主題文獻站（papers/）。

3

研究架構

SPEC

Stage A 邏輯與缺口對齊評判 → Stage B 你確認 Problem/Aim/Objectives → Stage C 規劃框架＋流程圖 → Stage D 框架修正協作（整條鏈唯一的正式迴圈），6 種偏誤類型幫你我對話時快速定位問題。

4

研究設計

SPEC

Stage A 技法提案（半結構訪談/日記法/情境訪查/RtD……）→ Stage B 對話共創執行細節 → Stage C 雙向可回溯性檢查＋依典範套嚴謹判準。強制產出研究倫理與同意書。

5

洞見萃取

SPEC

九層框架（Raw Data→…→Implication），Stage A 逐句編碼 → Stage B 跨受訪者聚合 → Stage C 詮釋（Why 最多 2 個候選）。整條流程的最後一站。

一個研究主題資料夾長怎樣 

<主題資料夾>/
  00_編輯歷程.md        里程碑摘要（細節交給 git log）
  01_文獻探討/          文獻蒐集：背景知識／近三年研究／研究缺口
  papers/               精讀陪讀：文獻站（逐段導讀、Critical Form、筆記）
  02_研究問題/          研究架構 Stage A/B
  03_研究架構/          研究架構 Stage C
  04_研究方法/          研究設計（含研究倫理與同意書）
  05_原始資料/          訪談逐字稿／日記（Notion 轉錄後匯出）
  06_結果/              洞見萃取（含對應研究框架）
  07_討論/              你自己手動寫

一個 repo 裝多個主題資料夾，透過 GitHub Pages 發布；論文 PDF 與 keepPrivate/ 不進 git。詳見 研究主題Repo_資訊架構.md。

貫穿全部步驟的原則

  • 一律手動觸發，沒有檔案監看/自動化，每個 Stage 之間你明確說可以才繼續
  • 詮釋層（Why／Insight／推論／缺口判斷）一定標「推論」，AI 只提案，不能替你下結論
  • 每個決策都要附「原因／限制／影響」，不是只寫「選了什麼」
  • 雙向可回溯性：訪談題目對得到框架構念，框架構念也要有題目對應，兩邊都不能有漏洞
  • 敏感研究一定要有倫理與同意書討論，不是選配
  • 批次處理多篇論文前，先列候選與優先序給你確認
